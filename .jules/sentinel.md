## 2026-06-18 - [IDOR and Existence Leakage in Condition Lifecycle Service]
**Vulnerability:** The `ConditionLifecycleService` methods (`applyCondition`, `removeCondition`, and `attemptSave`) were using a "check-then-act" pattern for authorization. While they performed pre-flight ownership checks, the actual database operations (`INSERT`, `UPDATE`, and `SELECT`) did not incorporate ownership filters, leaving the system vulnerable to race conditions and existence leakage.
**Learning:** Even with centralized authorization helpers, data-modifying and sensitive retrieval methods must implement defense-in-depth by ensuring every database operation is atomic and explicitly scoped to the authenticated user's permissions.
**Prevention:** Incorporate dual-ownership checks (`userId` AND `ownerId` for characters, campaign ownership for campaigns) directly into the `WHERE` clause of `UPDATE` and `SELECT` queries, and use `INSERT ... SELECT` patterns for `INSERT` operations. This ensures that the database itself gates the operation based on the user's identity in a single round-trip.

## 2026-02-15 - [WorkOS User ID UUID Validation Bypasses/Failures in Fog of War Router]
**Vulnerability:** The Fog of War router defined inputs using `z.string().uuid()` for `targetUserId` fields in endpoints like `reveal`, `revealBatch`, `conceal`, and `concealBatch`. Because the application uses WorkOS (not Supabase Auth) for identity management, user IDs are non-UUID strings (e.g., `user_01KAT...`). Strictly validating them as UUIDs in tRPC schemas resulted in valid target user IDs being rejected, causing authentication and state sharing failures between authorized session participants.
**Learning:** System user identifiers must always be validated based on the exact format of the backing authentication provider. Assuming all user IDs are UUIDs when transitioning/integrating third-party enterprise auth platforms like WorkOS can lead to severe operational issues.
**Prevention:** Always validate WorkOS-based user identifiers as `z.string()` (without `.uuid()`) in schemas and route input validations.
