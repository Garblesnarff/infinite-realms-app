## Project title and tagline

**Infinite Realms Companion**

A tabletop party companion through MCP, with a simulated Alexa+ browser client.

## Description draft

Tabletop players need to keep track of who is present, what the party can
see, and what their characters can do. Infinite Realms Companion gives a
player a small browser interface for inviting a companion, reading the
current scene, sending a companion's spoken line and requesting a skill roll.

The project connects a self-hosted Model Context Protocol server to Infinite
Realms' HTTP companion API. Six MCP tools expose joining, reading the scene,
speaking, rolling, listing companions and leaving. The simulated Alexa+
client initializes the MCP connection, lists tools and calls them over
Streamable HTTP, with a visible request/result log. Short text commands and
a scripted sequence demonstrate the experience. Optional browser speech
features depend on the browser; text input is the demonstrated baseline.

The upstream game enforces session ownership and returns redacted scene
data. Rolls are resolved by the game server; the client displays the returned
d20, modifier and total. A speech line is supplied by the user or script,
not generated by an autonomous companion agent. This is a simulated Alexa+
experience, not a connection to Amazon's Alexa+ partner service.

The existing Infinite Realms game predates the hackathon. The submitted new
work is its companion MCP server and simulated browser client. The standalone
companion source is prepared for MIT publication, while the game backend
remains separately licensed and is reached only through its HTTP API.
Judges need privately supplied API access and synthetic session instructions;
the public repo does not include the backend or credentials.

## Challenges and next work

The companion initially imported app service types. The standalone export
uses only local public HTTP wire declarations so it can typecheck independently
without shipping the game implementation. Browser tests initially depended
on a Chrome executable unavailable in CI; the app contract tests now use
jsdom with the real client module and MCP transport. These tests stay in the
app repository; they are not claimed as exported standalone tests.

Real bearer credentials expire. Account linking and automatic refresh remain
future work; judge access needs an explicit renewable arrangement. The demo
does not show combat or claim autonomous decision-making.
